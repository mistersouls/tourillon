## Summary

This proposal specifies the full client-facing KV operation protocol for Tourillon: the
write path (`kv.put`, `kv.delete`) with quorum-W fanout, sloppy-quorum hinted handoff,
and background hint replay; the read path (`kv.get`) with quorum-R fanout and read
repair; the four envelope kinds (`kv.put`, `kv.get`, `kv.delete`, `kv.replicate`);
and the three CLI commands (`tourctl kv put`, `tourctl kv get`, `tourctl kv delete`).
The coordinator uses `SimplePreferenceStrategy.preference_list()` to build a
per-partition preference list, enforces a `READY`-only phase guard for writes and a
`READY | DRAINING` guard for reads, and feeds `ProbeManager.data_fd` — introduced in
proposal 003 — on every fanout success or failure. Hint replay uses the same
`kv.replicate` envelope as normal write fanout; the `tag` field distinguishes a hint
replay from a primary write on the receiver side. Concurrent write and read fanout are
coordinated via `WaitGroup[str]` from `core/structure/waitgroup.py`. Hint storage and
replay are driven entirely through the `PartitionHint` port and `PartitionStore` defined
in `core/ports/storage.py` and implemented in `tourillon/core/services/kv/store.py` (proposal 005). No
amendments to this proposal are permitted; proposals 007–008 extend it only through new
`Dispatcher` registrations and new TOML sections.

---

## Motivation

Proposals 001–005 build the foundations (bootstrap, ring, gossip, inspect, rebalance)
but leave the cluster unable to serve any data. Three additional problems must be solved
before the cluster is useful:

1. **Client writes** — A client must be able to write a key-value pair to the cluster
   and receive a durable, causally-ordered confirmation. Without a coordinator write path
   that fans out to W replicas, the cluster stores nothing.

2. **Client reads** — A client must be able to retrieve the most-recent version of a
   key, even when some replicas are stale. Without quorum-R fanout and read repair,
   reads are neither consistent nor linearisable within the HLC ordering guarantee.

3. **Availability under transient failures** — When one or more replicas are temporarily
   unavailable (suspect in `data_fd`) the cluster must remain writable by routing writes
   to handoff targets and storing hints. Without hinted handoff and hint replay, a single
   replica failure causes writes to stall until the node recovers.

Without this proposal, a fully-joined Tourillon cluster cannot serve any KV traffic.

## CLI contract

### `tourctl kv put`

```
$ tourctl kv put <key> <value> [--keyspace <ks>] [-w <n>] [--addr <host:port>] [--json]
```

Connects to the coordinator node at `--addr` (default: value of `TOURCTL_ADDR`
environment variable or the `current-context` entry in `contexts.toml`) over mTLS,
sends a `kv.put` envelope, and prints confirmation to stdout.

**Flags:**

| Flag | Default | Description |
|---|---|---|
| `--keyspace <ks>` / `-k` | `default` | Logical keyspace name (UTF-8 string, encoded to bytes). |
| `--quorum-write <n>` / `-w` | _(coordinator default)_ | Required write ack count. Overrides the server-side quorum formula for this request. |
| `--addr <host:port>` | context default | Coordinator KV listener address. |
| `--json` | false | Emit machine-readable JSON to stdout. |

**Success output:**

```
✓  user:001  written  [hlc 2026-05-31T10:23:01.123Z · #0001 · node-a, acks 2]
```

**`--json` output:**
```json
{"hlc": {"wall_ms": 1748700000000, "counter": 1, "node_id": "node-a"}, "replicas": 2}
```

**Error cases:**

```
$ tourctl kv put foo bar --addr 10.0.0.1:7200
✗  connection refused (10.0.0.1:7200)
[exit 2]

$ tourctl kv put foo bar -w 3
✗  write failed: quorum unavailable (1/3 acks, timeout after 50ms)
[exit 3]

$ tourctl kv put foo bar
✗  write rejected: node is not READY (current phase: DRAINING)
[exit 3]
```

### `tourctl kv get`

```
$ tourctl kv get <key> [--keyspace <ks>] [-r <n>] [--addr <host:port>] [--json]
```

Connects to the coordinator, sends a `kv.get` envelope, and prints the result.

**Flags:**

| Flag | Default | Description |
|---|---|---|
| `--keyspace <ks>` / `-k` | `default` | Logical keyspace. |
| `--quorum-read <n>` / `-r` | _(coordinator default)_ | Required read response count. |
| `--addr <host:port>` | context default | Coordinator KV listener address. |
| `--json` | false | Emit machine-readable JSON to stdout. |

**Case 1 — confirmed version (stdout):**
```
✓  confirmed
   key       user:001
   keyspace  default
   value     Alice
   hlc       2026-05-31T10:23:01.123Z · #0001 · node-a
   replicas  2/2
```

**Case 1 — confirmed tombstone (key deleted) (stdout):**
```
✓  confirmed  (deleted)
   key       user:001
   keyspace  default
   hlc       2026-05-31T10:24:15.001Z · #0001 · node-a
   replicas  2/2
```

**Case 2 — uncertainty (quorum reached but no version confirmed) (stdout):**
```
⚠  uncertain — 2 candidates, none confirmed  (replicas disagree)
   #  value  hlc                              replicas
   1  Alice  2026-05-31T10:23:01.123Z…node-a  1/2
   2  Bob    2026-05-31T10:22:59.807Z…node-b  1/2
```

**Key not found (stdout):**
```
✗  not found
```

Exit code `0`; message on stdout.

**Case 3 — quorum unavailable (stderr, exit 3):**
```
✗  read failed: quorum unavailable (1/2 replicas responded)
```

**`--json` output (case 1):**
```json
{
  "versions": [
    {
      "confirmed": true,
      "value": "Alice",
      "hlc": {"wall_ms": 1748700000000, "counter": 1, "node_id": "node-a"},
      "count": 2,
      "quorum_write": 2
    }
  ]
}
```

The `value` field in `--json` is the msgpack-decoded Python value serialised as
JSON. Raw bytes that cannot be represented natively in JSON are rendered as
`{"_type": "bytes", "_value": "<base64>"}`.

**`--json` output (key not found):**
```json
{"versions": []}
```

### `tourctl kv delete`

```
$ tourctl kv delete <key> [--keyspace <ks>] [-w <n>] [--addr <host:port>] [--json]
```

Sends a `kv.delete` envelope. The coordinator writes a `Tombstone` with a freshly
ticked `HLCTimestamp` and fans it out to W replicas.

**Flags:** same as `kv put`.

**Success output:**

```
✓  user:001  deleted  [hlc 2026-05-31T10:24:15.001Z · #0001 · node-a, acks 2]
```

**`--json` output:**
```json
{"hlc": {"wall_ms": 1748700000001, "counter": 0, "node_id": "node-a"}, "replicas": 2}
```

**Error cases:** identical exit-code semantics to `kv put`.

## Design

### Data model

#### `KvConfig`

Parsed from the `[kv]` section of `config.toml`:

```toml
[kv]
fanout_timeout         = "50ms"   # per-RPC deadline for replica fanout; mandatory
hint_replay_concurrency = 2       # max concurrent hint-replay streams (default: 2)
```

`fanout_timeout` is parsed by `parse_duration()` during config loading in
`tourillon/core/services/config.py` into a
`float` (seconds). An absent or unparseable value is a fatal startup error.
`hint_replay_concurrency` is a plain `int`; defaults to `2` if absent.

#### `KvCoordinator` (`tourillon/core/services/kv/coordinator.py`)

The stateful domain object that handles a single KV operation end-to-end. Injected
dependencies:

```
storage          Storage            — partition store access (proposal 005)
probe_mgr        ProbeManager       — data_fd for fanout feedback (proposal 003)
strategy         PlacementStrategy  — preference list builder (proposal 002)
partitioner      Partitioner        — maps address hash → PartitionPlacement
topology         TopologyManager    — current ring + registry snapshot
clock            HLCClock           — hybrid logical clock (shared, asyncio.Lock guarded)
clock_lock       asyncio.Lock       — serialises HLCClock access
node_state       NodeState          — local node's current phase
config           KvConfig
```

Public API (all `async def`):

```python
async def put(self, keyspace: bytes, key: bytes, value: bytes) -> HLCTimestamp: ...
async def get(self, keyspace: bytes, key: bytes) -> Record | None: ...
async def delete(self, keyspace: bytes, key: bytes) -> HLCTimestamp: ...
async def replicate_local(self, pid: int, record: Record) -> None: ...
async def store_hint(self, pid: int, node_id: str, record: Record) -> None: ...
async def start_hint_replay(self) -> None: ...  # spawns background task
async def stop_hint_replay(self) -> None: ...
```

#### `HintReplayLoop` (`tourillon/core/services/kv/hint_replay.py`)

Background `asyncio.Task` that scans the local hint store and replays outstanding
hints to recovered nodes. Injected with `Storage`, `ProbeManager`, `Partitioner`,
`TopologyManager`, `TcpClient` (infra adapter), and `KvConfig`.

```python
async def run(self) -> None:
    """Main loop; runs until cancelled. Calls _replay_node() for each
    non-suspect node that has pending hints, bounded by
    config.hint_replay_concurrency concurrent streams."""
    ...

async def _replay_node(self, node_id: str) -> None:
    """Iterate PartitionHint.iter() for all pids, send kv.replicate with
    hint tag to the recovered node, delete hints on success."""
    ...
```

#### Quorum formulas

Given `rf = len(preference_list)` (the actual number of eligible replicas for this
partition in the current topology):

```
W = (rf // 2) + 1          # write quorum (strict majority)
R = rf - W + 1             # read quorum (guarantees R + W > rf)
```

Examples:

| rf | W | R |
|----|---|---|
| 1  | 1 | 1 |
| 2  | 2 | 1 |
| 3  | 2 | 2 |
| 4  | 3 | 2 |
| 5  | 3 | 3 |

If `rf == 0` (no eligible replicas in this partition), the operation fails immediately
with a quorum error before any fanout is attempted.

### Phase guards

| Operation | Allowed phases | Rejection message |
|-----------|---------------|-------------------|
| `put` / `delete` (coordinator role) | `READY` | `"node is not READY; writes not accepted (current phase: <phase>)"` |
| `get` (coordinator role) | `READY`, `DRAINING` | `"node is not READY or DRAINING; reads not accepted (current phase: <phase>)"` |
| `kv.replicate` (replica role) | `READY`, `DRAINING` | `"replica not accepting writes (current phase: <phase>)"` — reply with error envelope |

Phase is read from `NodeState` at the start of each handler invocation. A node in
`JOINING` or `IDLE` rejects all KV traffic. A node in `DRAINING` accepts reads as a
replica (via `kv.replicate` / `kv.get` fan-out) and accepts reads as a coordinator, but
rejects coordinator-role writes.

---

### Write path (coordinator)

```
[coordinator C receives kv.put or kv.delete from client]

1.  Phase guard: C must be READY. If not, reject immediately.
2.  Compute Address(keyspace=keyspace, key=key).
3.  Hash address bytes: hash_val = partitioner.hash(address.to_bytes()).
4.  placement = partitioner.placement_for(hash_val) → PartitionPlacement
    pid = placement.pid
5.  preferences = await strategy.preference_list(placement, topology, probe_mgr)
6.  rf = len(preferences); W = (rf // 2) + 1
    If rf == 0: fail with quorum error (exit 3).
7.  async with clock_lock: ts = clock.tick()
8.  Build record:
      put    → Version(address, metadata=ts, value=value, quorum_write=W)
      delete → Tombstone(address, metadata=ts, quorum_write=W)
9.  Fanout: fan_out_write(pid, record, preferences, W)
      wg: WaitGroup[str] = WaitGroup()
      await wg.add(len(preferences))
      For each entry in preferences (fire asyncio.create_task per entry):
        target = entry.handoff if entry.handoff else entry.node_id
        tag = Tag(kind=TagKind.LIVE)   # normal primary write tag
        try:
          If target == self.node_id:
            await storage.open_by_pid(pid).put()/tombstone()  (local write)
            await wg.done(target, success=True)
          Else:
            ok = await _send_replicate(target, pid, record, tag=tag)
            await wg.done(target, success=ok)
          On success path: record_data_success(target)
        except:
          record_data_failure(target)
          If entry.handoff (sloppy quorum: handoff target failed):
            await store_hint(pid, entry.node_id, record)
          Else:
            await store_hint(pid, entry.node_id, record)
          await wg.done(target, success=False)
      success_nodes, failed_nodes = await wg.wait()
      If len(success_nodes) < W: fail with quorum error.
10. Return ts.
```

**Sloppy quorum detail**: when `entry.handoff is not None`, the coordinator writes to
the handoff target `B` (live write, counted toward W) _and_ stores a hint for the
original owner `A` (so that when A recovers, the hint replay sends A the write it
missed). The hint is stored in the coordinator's local `PartitionHint(pid, A.node_id)`.

`WaitGroup[str]` is keyed by `target` (the actual destination node_id); `success_nodes`
contains all node_ids that acked within `fanout_timeout`; acks ≥ W → success.

### Read path (coordinator)

```
[coordinator C receives kv.get from client]

1.  Phase guard: C must be READY or DRAINING. If not, reject.
2.  Compute Address, hash, placement, pid, preferences (steps 2–5 of write path).
3.  readable = [e for e in preferences if e.readable]
    rf = len(readable); R = rf - ((rf // 2) + 1) + 1
    If rf == 0: fail with quorum error.
4.  Fan out kv.get to all readable entries concurrently via WaitGroup[str]:
      wg: WaitGroup[str] = WaitGroup()
      await wg.add(len(readable))
      results: dict[str, Record | None] = {}
      For each readable entry e (fire asyncio.create_task per entry):
        try:
          If e.node_id == self.node_id:
            record = await storage.open_by_pid(pid).get(address)
          Else:
            record = await _send_get(e.node_id, pid, address)  # kv.get envelope
          record_data_success(e.node_id)
          results[e.node_id] = record
          await wg.done(e.node_id, success=True)
        except:
          record_data_failure(e.node_id)
          await wg.done(e.node_id, success=False)
      success_nodes, _ = await wg.wait()
5.  If len(success_nodes) < R: fail with quorum error.
6.  winner = max(results[n] for n in success_nodes,
                 key=lambda r: r.metadata if r else HLCTimestamp(0,0,""))
    (None / missing key counts as the lowest possible timestamp)
7.  Read repair: for each n in success_nodes where results[n] != winner:
      await _send_replicate(n, pid, winner, tag=Tag(kind=TagKind.LIVE))
      (fire-and-forget; failures call record_data_failure(), never raise)
8.  Advance local clock: async with clock_lock: clock.update(winner.metadata) if winner
9.  Return winner (None if all results are None, meaning key not found).
```

### Hinted handoff

Hinted handoff activates in two scenarios:

1. **Explicit handoff** — `entry.handoff is not None` in the preference list: the primary
   owner is in `_ALWAYS_HANDOFF_PHASES` (DRAINING or PAUSED), so `SimplePreferenceStrategy`
   already selected a handoff target. The coordinator writes to the handoff target
   (counted toward W) and stores a hint for the primary owner.

2. **Implicit handoff** — `entry.suspect is True`: the primary is READY but suspected by
   `data_fd`. `SimplePreferenceStrategy` provides a handoff target; the coordinator writes
   to the handoff target and stores a hint for the suspect primary.

In both cases the hint is stored locally by the coordinator:

```python
store = storage.open_by_pid(pid)
hint = store.hint(for_node_id)      # PartitionHint scoped to (pid, for_node_id)
if isinstance(record, Version):
    await hint.put(record.address, record.value, record.metadata)
else:
    await hint.tombstone(record.address, record.metadata)
```

The hint persists across coordinator restarts; it is deleted only after successful
replay.

---

### Hint replay

`HintReplayLoop.run()` is a perpetually-running `asyncio.Task`, started by
`start_hint_replay()` and cancelled by `stop_hint_replay()`. On each iteration:

```
1.  Enumerate all (pid, node_id) pairs that have hint entries by scanning
    Namespace.TAGS for TagKind.HINT entries across all local pids.
2.  For each unique node_id with hints:
      If await probe_mgr.is_suspect(node_id): skip (node not yet recovered).
3.  Replay up to config.hint_replay_concurrency node_id streams concurrently
    using asyncio.TaskGroup:
      For each (pid, node_id) pair:
        hint = storage.open_by_pid(pid).hint(node_id)
        async for tagged_record in hint.iter():
          # _send_replicate carries the original hint tag bytes from storage.
          # tombstone=True/False drives PartitionStore.tombstone() vs .put()
          # on the receiver side; the tag.kind distinguishes hint replay from
          # a primary write for logging and HLC purposes.
          await _send_replicate(
              node_id, pid, tagged_record,
              tag=tagged_record.tag,
              tombstone=isinstance(tagged_record, Tombstone),
          )
          On success: delete hint from BackendStorage (via BackendStorage.delete())
                      record_data_success(node_id)
          On failure: record_data_failure(node_id); break inner loop (retry next cycle)
4.  Sleep for a short interval (not configurable in this proposal; 1 s default).
```

Hint replay is best-effort. If a node permanently fails (transitions to `FAILED` in the
registry), its hints are eventually expired by the GC engine.

### Envelope kinds

All payloads are msgpack-serialised dicts.

#### `kv.put` (client → coordinator)

```json
{
  "keyspace": <bytes>,
  "key":      <bytes>,
  "value":    <bytes>
}
```

**Response** (coordinator → client, same connection):

```json
{
  "ok":  true,
  "hlc": { "wall_ms": 1748700000000, "counter": 0, "node_id": "node-a" }
}
```

Error response:

```json
{
  "ok":    false,
  "error": "write quorum not met (needed 2, got 1 acks within fanout_timeout)",
  "code":  3
}
```

---

#### `kv.get` (client → coordinator, also coordinator → replica)

```json
{
  "keyspace": <bytes>,
  "key":      <bytes>,
  "pid":      42         // omitted when sent by CLI client; populated by coordinator
                         // for replica fan-out so the replica can open_by_pid directly
}
```

**Response — version found:**

```json
{
  "found":     true,
  "tombstone": false,
  "keyspace":  <bytes>,
  "key":       <bytes>,
  "value":     <bytes>,
  "hlc":       {"wall_ms": 1748700000000, "counter": 1, "node_id": "node-a"},
  "quorum_write": 2
}
```

**Response — key not found:**

```json
{ "found": false }
```

**Response — tombstone (key deleted):**

```json
{
  "found":     true,
  "tombstone": true,
  "keyspace":  <bytes>,
  "key":       <bytes>,
  "value":     null,
  "hlc":       {"wall_ms": 1748700000001, "counter": 0, "node_id": "node-a"},
  "quorum_write": 2
}
```

`tombstone: bool` replaces the old `"kind": "version"/"tombstone"` discriminator,
consistent with `kv.replicate`. When fanning out to replicas, the coordinator adds
`"pid": <int>` as a top-level field so the replica can call `open_by_pid` directly.

#### `kv.delete` (client → coordinator)

```json
{
  "keyspace": <bytes>,
  "key":      <bytes>
}
```

**Response:** same shape as `kv.put` response.

#### `kv.replicate` (coordinator → replica, read repair, and hint replay)

The single internal replication envelope. Used for:
- **Write fanout**: coordinator fans out a new write to preference-list replicas.
- **Read repair**: coordinator repairs a stale replica after a quorum read.
- **Hint replay**: `HintReplayLoop` resends a stored hint to a recovered node.

The `tag` field is the serialised `Tag` stored (or to be stored) in `Namespace.TAGS`
for this record. Its `kind` byte distinguishes a hint replay (`TagKind.HINT`) from a
primary write (`TagKind.LIVE`). The `tombstone` flag disambiguates a `value=null`
Tombstone from a Version with a null/empty value.

```json
{
  "pid":          42,
  "keyspace":     <bytes>,
  "key":          <bytes>,
  "value":        <bytes> | null,
  "tag":          <bytes>,
  "tombstone":    false,
  "hlc":          {"wall_ms": 1748700000000, "counter": 1, "node_id": "node-a"},
  "quorum_write": 2
}
```

- `tombstone=true` → receiver calls `PartitionStore.tombstone()`; `value` is `null`.
- `tombstone=false` → receiver calls `PartitionStore.put()`; `value` is the record bytes.
- `tag` bytes are passed as-is to the storage layer and written to `Namespace.TAGS`.

**Response (ack):**

```json
{ "ok": true }
```

Error ack:

```json
{ "ok": false, "error": "replica not accepting writes (current phase: JOINING)" }
```

### Core invariants

**Invariant §1 — Phase guard before fanout:**
The coordinator reads `NodeState.phase` at the start of every operation and rejects
immediately if the phase does not satisfy the guard. The phase is never re-checked
mid-fanout; the guard is a pre-condition, not a continuous lock.

**Invariant §2 — HLCClock access is serialised:**
All reads and writes to `HLCClock` (both `tick()` and `update()`) are performed inside
`async with clock_lock`. `HLCClock` is not coroutine-safe; the lock ensures
monotonicity.

**Invariant §3 — `data_fd` is fed on every fanout outcome:**
Every individual fanout RPC (to a replica or handoff target) calls either
`record_data_success(node_id)` or `record_data_failure(node_id)` on `ProbeManager`.
There are no silent discards. Control-plane envelopes (`gossip.*`, `node.inspect`,
`node.pause`, `node.resume`) **do not** feed `data_fd`.

**Invariant §4 — Quorum counted before commit:**
The coordinator counts acks **after** all fanout tasks complete (or timeout). It
does not optimistically commit the operation to the client before W acks are received.

**Invariant §5 — Hint stored for primary, not handoff target:**
When sloppy-quorum routing sends a write to handoff target B on behalf of primary A,
the hint is stored for A (i.e., `hint = store.hint(A.node_id)`), not for B. The hint
replay loop sends the hinted write directly to A when A recovers. B's live copy is
not disturbed.

**Invariant §6 — Read repair is fire-and-forget:**
`kv.replicate` sent for read repair is not awaited for a quorum confirmation. Failure
in a read repair RPC calls `record_data_failure()` and is logged at `WARNING` level, but
never propagates to the client.

### Sequence / flow

#### Successful put (rf=3, W=2, all replicas healthy)

```
Client ──kv.put──► Coordinator C
C: phase guard OK (READY)
C: tick HLC → ts₀
C: placement → pid=42; preference_list = [A, B, D] (rf=3, W=2)
C: WaitGroup[str].add(3); fire 3 concurrent _send_replicate tasks (tag=LIVE)
A, B, D: receive kv.replicate; tombstone=False; call PartitionStore.put(); ack OK
C: WaitGroup.wait() → success=[A, B, D], failed=[]
C: 3 acks ≥ W=2; record_data_success(A), record_data_success(B), record_data_success(D)
C: ──{ok:true, hlc:ts₀}──► Client
```

#### Put with one suspect replica (rf=3, W=2, node A suspect)

```
C: preference_list = [
     PreferenceEntry(node_id=A, suspect=True, handoff=X),
     PreferenceEntry(node_id=B, suspect=False, handoff=None),
     PreferenceEntry(node_id=D, suspect=False, handoff=None),
   ]
C: for entry A: target = X (handoff); send kv.replicate to X → ack OK
                store hint(pid, A): hint.put(addr, value, meta)
                record_data_failure(A)  [A is already suspect, this is the hint path]
C: for entry B: send kv.replicate to B → ack OK; record_data_success(B)
C: acks(B + X) = 2 ≥ W=2 → success
```

Note: `record_data_failure(A)` is called because A could not receive the write
directly. The handoff target X receives a normal `kv.replicate`; X's outcome feeds
`record_data_success(X)` or `record_data_failure(X)`.

#### Get with read repair (rf=3, R=2)

```
Client ──kv.get──► C
C: phase guard OK; preference_list readable=[A, B, D]
C: fan out kv.get(pid=42, addr) to A, B, D in parallel
   A returns Version(ts=100), B returns Version(ts=100), D returns Version(ts=90)
C: R=2 responses received; winner = ts=100
C: D is stale → send kv.replicate(pid=42, Version(ts=100)) to D (fire-and-forget)
   record_data_success(A), record_data_success(B), record_data_success(D)
C: ──{found:true, record:Version(ts=100)}──► Client
```

#### Hint replay

```
HintReplayLoop iteration:
  Scan tags: pid=42 has hints for node_id=A (2 hints)
  probe_mgr.is_suspect(A) → False (A has recovered)
```

### Error paths

| Condition | Outcome |
|---|---|
| Phase guard fails (write on non-READY) | Exit 3; `"node is not READY; writes not accepted"` |
| Phase guard fails (read on non-READY/DRAINING) | Exit 3; `"node is not READY or DRAINING; reads not accepted"` |
| `rf == 0` (no eligible replicas) | Exit 3; `"no eligible replicas for partition <pid>"` |
| `acks < W` within `fanout_timeout` | Exit 3; `"write quorum not met (needed W, got N)"` |
| `responses < R` within `fanout_timeout` | Exit 3; `"read quorum not met (needed R, got N)"` |
| Replica rejects `kv.replicate` (wrong phase) | Counted as failure; `record_data_failure(node_id)` |
| `kv.replicate` (hint) replay failure | `record_data_failure(node_id)`; retry next loop cycle |
| Connection refused / TLS error | Exit 2 (CLI) or propagated as fanout failure (server) |
| `store_hint` raises `StorageError` | Log error; do not count as ack; `record_data_failure(node_id)` |
| `PartitionStore.put/tombstone` raises `StorageError` on local write | Treat as fanout failure; `record_data_failure(self.node_id)` |

## Design decisions

### Decision: Coordinator stores hints (not handoff target)

**Alternatives considered:** The handoff target B receives `kv.replicate` with a
`hint_for` field, stores the hint locally, and replays it independently.
**Chosen because:** Storing hints at the coordinator avoids adding a new envelope kind
(`kv.hint.store`) and keeps the hint lifecycle entirely within one process. The
coordinator already has `Storage` access and can iterate hints during its own replay
loop. The Dynamo-style "handoff target holds hints" model requires the handoff target to
implement its own replay loop and expiry logic; that complexity is deferred to a future
cluster-manager proposal if multi-hop hints become necessary.

---

### Decision: `kv.get` doubled as coordinator-to-replica read fanout

**Alternatives considered:** A separate `kv.read.replica` envelope kind for internal
reads, keeping `kv.get` as a purely client-facing envelope.
**Chosen because:** The read payload shape is identical for client requests and internal
fan-out (keyspace + key + pid). Reusing `kv.get` with an optional `pid` field (omitted
by the CLI client, populated by the coordinator for replica fan-out) avoids an
unnecessary envelope kind. Replicas that receive `kv.get` with a pid field bypass
the coordinator-side hash and placement steps.

---

### Decision: W and R derived from actual `rf`, not configured value

**Alternatives considered:** Expose `quorum_write` and `quorum_read` as explicit
`[kv]` config fields.
**Chosen because:** The actual rf can be lower than the configured replication factor
when the cluster has fewer live nodes (e.g. during bootstrap or after failures). Using
`rf = len(preference_list)` makes quorum adaptive and prevents writes from stalling
forever when fewer nodes are available, at the cost of weaker durability guarantees in
degraded mode. Operators who need a strict minimum replication factor can add a
`min_replication_factor` guard in a future proposal.

---

### Decision: Read repair is fire-and-forget

**Alternatives considered:** Await read repair acks before returning to the client (read
repair as a synchronous operation).
**Chosen because:** Making read repair synchronous would add latency to every quorum-R
read that encounters a stale replica. The repair is an optimisation, not a
correctness requirement — correctness is already ensured by the quorum-R response
containing the highest-HLC value. Failures in read repair are surfaced via
`record_data_failure()`, which feeds `data_fd`, so persistently stale replicas will
eventually be suspected.

---

### Decision: `fanout_timeout` is mandatory

**Alternatives considered:** Default to `"100ms"` if absent.
**Chosen because:** An absent `fanout_timeout` silently produces unbounded fanout
latency that is invisible to operators. Forcing the operator to set it explicitly (at
startup) ensures that the cluster's latency contract is always deliberate. A missing
`fanout_timeout` is a fatal startup error consistent with the unit-embedded value
convention in §6 of the plan.

## Out of scope

- Tombstone eviction and garbage collection of expired hints — covered by proposal 008.
- `PAUSED` phase interaction with KV writes — write routing handles `PAUSED` correctly
  (always-handoff), but the full pause/resume lifecycle is out of scope for this proposal.
- Multi-coordinator conflict resolution (last-writer-wins via HLC is the only merge
  strategy; vector clocks or CRDTs are not addressed).
- Client-side retries and timeout configuration — clients are expected to retry at the
  application level; no retry loop is built into the coordinator or CLI.
- Conditional writes (compare-and-swap, check-and-set) — not in scope.
- Key listing / range scans over the KV namespace — not in scope; `PartitionStore.scan()`
  exists for rebalance use only and is not exposed as a client API.
- Cross-keyspace transactions — out of scope.
- Backpressure / rate limiting on coordinator fanout — deferred to a future
  operations proposal.
- Storage backend selection for the hint store — the hint store shares the same
  `BackendStorage` segment as the partition data; no separate configuration is required.
